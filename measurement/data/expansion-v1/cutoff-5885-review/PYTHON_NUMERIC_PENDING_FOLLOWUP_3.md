## Why the three clarity holds are narrower than numerical failure

The prompts for 0566, 0608 and 0629 specify float storage/output but do not explicitly instruct callers to accept native conversion exceptions, nor restrict the admitted numeric values to float-representable ones. Reference implementation choices alone cannot create that public error policy. Conversely, their float-output requirement means a huge-value OverflowError is not evidence that the implementation could simply preserve an exact answer as a finite float. The needed disposition is an explicit representation/error contract, not a fabricated numeric correctness metric.

This differs from frozen sample failures where a needless conversion or unstable intermediate prevents a small, representable answer (for example exact integer aggregation or a bounded limiting result). It also differs from 0518, whose potentially overflowing expression is supplied literally in the prompt. No reference/test changes are proposed under this review-only assignment.
