## Static hold witnesses and limits

### generation0359

Construct max_charge_ms=2, energy_per_ms=0, base_damage=0, bonus_damage=u32::MAX (swing/recovery arbitrary valid u32). Advance2 milliseconds while held, with zero energy. This is a tiny valid public input and immediately strikes.

The specified u32 saturating expression yields `sat_u32(MAX * 2) / 2 = 2147483647`; reference widens first and yields `(8589934590 / 2) = 4294967295`. The later u32 saturating addition with base0 does not erase the difference. The existing boundary test uses a nearly-MAX base and masks this discrepancy. This is a static arithmetic calculation, not an executed probe. A widened precise-ratio contract would be a different prompt and could justify the reference, but must not silently replace the explicit saturation instruction over its u32 operands.

### generation0396

This requires only three ledger transitions after construction plus finish, not a large collection or private state injection. Correct rejection/reservation handling must prevent accepting the incompatible balance growth, or the contract must explicitly permit restoration failure. The return-value choice for record is not the hold basis.
