# R24 Go full quality review — 2026-09-08

Gate 2. Exactly seven R24 Go generation candidates were reviewed statically in
full: 0102, 0160, 0276, 0327, 0382, 0542 and 0791. The frozen plan, run
contract, complete candidate prompts/references/known-bad implementations/tests,
immutable original parents, parent holds and selection evidence were read. No
generated code was executed, no candidate was changed, and no admission,
correction, cloud action or original-review credit is claimed here.

**Result: zero seven-criterion positives. Six test-only holds (0102, 0160,
0276, 0382, 0542, 0791) and one reference-plus-test hold (0327).** Every test
suite omits the defining recovery witness and therefore does not distinguish
its supplied realistic known-bad implementation. The references for the six
test-only holds are scoped and statically correct. The 0327 replacement mean
still overflows for three identical `math.MaxFloat64` values even though their
mathematical mean is finite.

These are candidate-quality dispositions only. The original parent holds
remain immutable, and a future test-only correction would require a separately
approved version. Candidate directionality has not been run or inferred.

## Per-candidate decisions

### exp-v1-recovery-r24-go-generation-0102 — test-only hold

The unchanged specification and API are clear. Account registration,
normalization, deterministic IDs, password digests, HMAC authentication,
verification and isolated sorted lookup form a substantive complete target.
The replacement reference now round-trips both raw-base64url segments and is a
minimal, idiomatic standard-library repair. The known-bad is the realistic
original implementation that accepts CR/LF ignored by Go's base64 decoder.

The independent tests verify canonical issuance, allowed token characters,
ordinary signature alteration and wrong-secret rejection, but never pass a
canonical token with appended newline or carriage return, nor an embedded
signature CR/LF. Consequently they do not exercise the recovered behavior and
the supplied known-bad can satisfy the suite. This is an independently authored
but behaviorally insufficient test suite, not a reference defect.

Minimal specification-only feedback: after authenticating and successfully
verifying the canonical token, require `token+"\n"`, `token+"\r"`, and a token
with CR/LF inserted into the signature segment to fail. Preserve account-store
state and all existing normalization, ID, secret-copy, tamper and isolation
controls. Do not inspect private counters or impose unpromised secondary return
values.

### exp-v1-recovery-r24-go-generation-0160 — test-only hold

Claims validation, exact standard-library JSON, HMAC over the encoded payload,
expiry and constant-time comparison are substantive and internally consistent.
The replacement reference decodes and re-encodes both segments before signature
verification, while retaining the frozen contract and standard-library-only
implementation. The original reference is a realistic known-bad because raw
base64url decoding tolerates CR/LF.

The tests cover deterministic issuance, no padding, malformed segment counts,
invalid encoding, signature alteration, JSON/claim failures and temporal
boundaries. They do not append or embed CR/LF in either token segment. Thus the
specific known-bad remains indistinguishable and the recovery is not quality
positive.

Minimal specification-only feedback: verify a canonical token at time zero,
then require the same token plus newline and carriage return, and an embedded
signature newline, to fail. Retain padding, extra-segment, signature, invalid
claim, unknown-field, trailing-JSON and expiry controls. Do not add JSON
canonicalization or error-secondary-output requirements absent from the prompt.

### exp-v1-recovery-r24-go-generation-0276 — test-only hold

The complete task combines exact signed claims, checked 86,400-second expiry,
future-issued rejection and secret-slice ownership. The replacement reference
performs canonical raw-base64url round trips while continuing to MAC the encoded
payload segment. Aside from formatting and ignored `hash.Write` return values,
the diff is limited to the selected token-spelling defect. The known-bad is a
realistic predecessor.

The suite tests exact generated bytes, overflow, temporal boundaries, malformed
segments, signature alteration, JSON/claim validation and later mutation of the
caller secret. It supplies no appended or embedded CR/LF token spelling. The
known-bad therefore is not behaviorally separated.

Minimal specification-only feedback: add canonical success at issuance time
and rejection for appended newline/carriage return and embedded signature
newline. Keep padding, tamper, future-issued, exact-expiry, overflow and JSON
controls. Do not add new key-spelling, resource or secondary-output policies.

### exp-v1-recovery-r24-go-generation-0327 — reference-and-test hold

The concurrent ledger remains a substantive target: zero-value operation,
atomic ordered append, finite-value validation, detached histories, min/max,
mean and concurrent access interact. The prompt/API, dependency isolation and
known-bad realism are positive. The independent suite covers these broad
behaviors, but contains no large-magnitude finite-mean witness at all.

The replacement algorithm is not generally overflow-safe:

```go
mean = mean*(n-1)/n + vs[i]/n
```

After two `math.MaxFloat64` values, `mean` is `math.MaxFloat64`; on the third
iteration `mean*(n-1)` overflows before division. Three identical finite values
therefore produce infinity although their mathematical mean is exactly
`math.MaxFloat64`. This violates the approved requirement that intermediate
arithmetic not overflow a representable mean. The test omission also means the
naive-sum known-bad is not distinguished.

This cannot be resolved by a test-only correction. A future reference version
must use arithmetic robust for repeated same-sign maxima as well as negative
maxima and cancelling opposite maxima. Its independent tests should require an
exact finite result for two and at least three identical positive maxima, two
and at least three identical negative maxima, a finite cancellation witness,
and ordinary fractional values with a justified tolerance. Preserve concurrency,
missing-key behavior, detached history, min/max and rejected-append atomicity.

### exp-v1-recovery-r24-go-generation-0382 — test-only hold

The frozen contract clearly distinguishes canonical JSON payload bytes from
canonical raw-base64url segment spelling and explicitly allows `now` before
`IssuedAt`. The replacement reference correctly round-trips both encoded
segments, MACs decoded raw JSON bytes as required, retains JSON canonicality and
uses `hmac.Equal`. Its scope and standard-library implementation are positive;
the original missing segment-spelling check is a realistic defect.

The tests cover canonical minting, pre-issuance verification, expiration,
malformed segments, signatures, JSON canonicality/claims and secret-slice
ownership. They do not alter raw-base64url spelling with appended or embedded
CR/LF. Thus they do not reject the supplied known-bad for its defining defect.

Minimal specification-only feedback: require a canonical token to succeed and
appended newline/carriage return plus embedded signature CR/LF to fail; include
a noncanonical payload-segment spelling while preserving the contract's MAC over
raw JSON. Keep the explicit pre-issued-time acceptance and existing malformed,
padding, claims and expiry cases.

### exp-v1-recovery-r24-go-generation-0542 — test-only hold

Polymorphic metric dispatch, call ordering, input preservation, validation and
zero-summary error behavior are substantive. The replacement reference narrows
nil detection to a nil interface or a typed nil pointer, exactly matching the
prompt. It properly permits nil-backed map/slice/function/channel values whose
defined value-receiver `Metrics` methods can execute. The overbroad reflection
switch in the known-bad is realistic.

The tests use ordinary struct resources, a nil interface and a typed nil
pointer, but define no named nil map, slice, function or channel implementing
`Resource`. The candidate reference and known-bad therefore behave identically
for every submitted test.

Minimal specification-only feedback: define at least one named map type with a
value-receiver `Metrics` method, pass its nil value through `Resource`, and
require the returned metrics/count with no error. A named nil slice or function
is a useful second control. Retain typed-nil-pointer rejection without calling
its method, ordered calls, invalid metric cases, zero summary and input-slice
preservation. Do not add panic shielding or aggregate-overflow policy.

### exp-v1-recovery-r24-go-generation-0791 — test-only hold

The typed configuration decoder and generic object decoder are a substantive
combined target. The replacement token-based decoder checks decoded key strings
exactly, rejects duplicates and wrong shapes, and preserves `UseNumber`,
duplicate-last generic-object behavior, privacy and ownership. It correctly
treats an escaped JSON key spelling that decodes to `label` as the same key.
The case-insensitive struct-field decoder is a realistic known-bad.

The suite covers canonical encoding/decoding, privacy, missing/duplicate/wrong
types, unknown lowercase fields, malformed/trailing documents, numeric bounds,
generic object semantics and detached nested results. It never supplies
`{"Label":"x","level":1}` or `{"label":"x","Level":1}`. Consequently it
does not distinguish the known-bad's case-insensitive key acceptance.

Minimal specification-only feedback: require canonical lowercase keys to
succeed and each differently cased required key to fail, including the two
single-key substitutions above. Retain duplicate, unknown, missing, wrong-type,
trailing, privacy, `UseNumber`, duplicate-last and ownership controls. Do not
reject valid escaped spellings of the same decoded key or label values merely
because they contain the substring `token`.

## Seven-criterion accounting

1. **Prompt clarity:** all seven problem texts are byte-identical to their
   immutable parents and sufficient to adjudicate the proposed behavior. No
   generated prompt expansion or domain restriction occurred.
2. **API consistency:** declared Go package, exported symbols, data shapes,
   error boundaries and runtime remain consistent. No private layout or
   unpromised trait/secondary-output behavior is required by this review.
3. **Test independence:** test-author provenance is clean: the author prompt
   contains only IDs and specifications, and emitted tests match candidate test
   files exactly. Behavioral sufficiency fails for every record because each
   defining witness is absent. Independence does not substitute for coverage.
4. **Non-triviality:** every full target is substantive; no disposition rests
   on patch size. Authentication/state, temporal validation, concurrent numeric
   aggregation, polymorphism, and strict/custom JSON behavior all exceed an
   elementary wrapper.
5. **Idiomatic code:** the six test-only references use ordinary standard-library
   Go appropriately. The 0327 reference's multiplication-before-division is a
   correctness defect despite otherwise idiomatic locking and ownership.
6. **Dependency isolation:** package `solution`, Go 1.22 support and standard
   library only. No network, external service or package dependency appears.
7. **Realistic known-bad failure:** all seven known-bads reproduce the bound
   parent defect and are neither stubs nor unrelated failures. None is rejected
   by its current independent suite; 0327 additionally has a defective proposed
   reference.
